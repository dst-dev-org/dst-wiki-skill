# 首次使用与知识库初始化

首次取得知识资产、保存配置或明确新建知识库时读取；只需定位工具或处理异常时，直接读对应小节。常规任务复用有效知识根，不重复安装、配置或建库。基础操作只需宿主能搜索／读写 Markdown 和所用证据目录，源码解压与工程环境分开准备。

## 取得知识资产

尚无知识资产时，向用户提供 [dst-wiki 知识仓](https://github.com/dst-dev-org/dst-wiki) 获取地址，可在仓库页面选择 **Code → Download ZIP** 下载，或要求 AI clone。用户提供其他仓库或来源目录时，以其指定来源为准。

目标保存位置由用户指定绝对路径；下载／clone 按明确请求执行，不猜其他仓库地址或自动获取。取得后确认新知识根可用；路径规则尚不明确时才读 [路径约定](paths.md)，不把取得成功等同证据有效。

## 保存配置

用户配置固定在 `~/.dst-wiki/config.json`，按以下条件保存绝对路径，不把路径写进 SKILL.md：

- 配置不存在，或有效配置对象中尚无 `knowledge_root`：用户明确指定 K 且检查通过后自动保存，简短告知保存位置；用户说明临时使用或不保存则跳过。新建空库须先完成初始化。
- 已有 `knowledge_root`：正常使用不重写；本次另指定路径只在本次生效，用户明确要求保存为默认位置或切换默认知识库时才更新。
- `toolbox_root` 仅实际需要、用户明确选定且检查有效后保存；更换已有默认值同样需明确要求。

首次保存可创建配置父目录和文件；已有有效 JSON 对象只合并需更新的字段，保留其他字段。配置损坏时保留原文件，按下节处理，不自动覆盖修复。保存失败时说明原因，继续使用本次已确认路径，不反复要求用户确认或阻断任务。

```json
{
  "knowledge_root": "<知识资产的实际绝对路径>"
}
```

执行前替换占位符；Windows 路径推荐 `/`。仅需定位 T 且尚未确认时，读 [工具箱路径约定](paths.md#t可选工具箱根)。当前仅支持用户级配置，没有项目级配置覆盖；本 Skill 与模组开发 Skill `dst-mod-dev-skill` 共用这份配置，定位知识根与可选工具箱，不固定目标模组。

## 定位工具与异常处理

仅所需路径／状态仍无法确认或需要重查相关项时使用脚本；有用户指定的 K 或待解析的配置，且有 PowerShell 时尝试一次内置检查，无需 Python 或读取其实现。K／S 已确认则复用，S 缺失时才读 [当前 Skill 根约定](paths.md#s当前-skill-根)；已知 K 用显式参数，否则由脚本读取用户配置。仅宿主要求执行授权时申请，无 PowerShell 则按下述约定人工检查。S／K 替换为实际绝对路径：

```powershell
& "<S>/scripts/resolve_paths.ps1"
& "<S>/scripts/resolve_paths.ps1" -KnowledgeRoot "<K>"
```

此脚本只解析与检查指定／配置路径，不搜索未登记的知识根。两处都没有 K 时，集中询问已有目录；尚未取得知识资产则按 [取得知识资产](#取得知识资产) 提供获取入口。

返回根目录和 Wiki 可用状态、源码结构与所记录版本、可选工具状态；不创建目录或写配置。显式 KnowledgeRoot 时不读用户配置，需要工具时另传 ToolboxRoot。其他环境直接读取配置文件 JSON，按相同约定检查目录；需要源码核验时再检查源码结构与 BUILD.txt。PowerShell 不是基础使用前置。源码状态的解释及历史快照参数见 [已有与历史快照](prepare-source.md#已有与历史快照)，仅需要时读取。

- 配置无效时给出实际配置文件／字段问题，不回退到猜测位置；用户本次明确路径可绕过失效配置。保存修复按用户给出的值进行。
- 路径指向文件时报告错误，要求实际目录。路径不存在或缺根索引时说明实际检查结果，先区分选错目录、部分知识与用户要求初始化，不猜替代位置或自动创建；`-AllowUninitialized` 的适用范围见下节。
- 宿主限制目录访问时说明所需目录／能力，不将访问失败说成源码不存在；包完整／链接有效不等于目录访问已获允许。

## 明确新建空库

只有用户要求创建并给出目标目录才初始化；缺根索引不等于建库授权。先查看目标中现有文件，保留已有知识和源码；按 [索引格式](../maintain/maintain-index.md#索引格式) 创建 `K/wiki/index.md`，写真实当前日期、`type: index`、`tags: [overview]`，并在正文说明当前为空库、尚无技术结论，不伪造技术结论或待建页链接。尚无知识类别时根索引保持短文，首篇落地再建其叶级索引／必要父入口；不预建所有分类。

明确初始化，或只读定位有源码但尚无 Wiki 的知识根时，可用以下命令：

```powershell
& "<S>/scripts/resolve_paths.ps1" -KnowledgeRoot "<K>" -AllowUninitialized
```

它允许目标目录尚不存在，返回 `knowledge_exists`／`wiki_available`，不会创建文件，也不授予建库权限。实际创建时建立根索引；按 [日志维护](../maintain/maintain-log.md) 在 `K/wiki/log.md` 追加初始化操作、实际目录与空库范围，保留已有历史。raw／output 由真实准备／工具任务再创建，不创建 Git 仓或修改忽略规则，除非本次有这些要求。

初始化导航不产生知识。无技术证据时只报告空库／待核验缺口，不生成 verified 页或推荐 demo；首篇生成按所选维护流程核验并登记，普通用户无需 AST／类型库流水线。

## 可用边界

| 当前资源 | 可执行范围 |
|---|---|
| 已有 Wiki，无源码／工具箱 | 查询已有结论、链接与结构检查；源码核验缺口可见 |
| Wiki＋可读源码，无工具箱 | 定向核验、生成／增修与人工登记，无 Python／Rust／LuaLS 前置 |
| 明确空库，无源码 | 初始化导航；技术内容等待实际依据，不发布未核验实现 |
| 非 Windows／无 PowerShell | 直接读取配置和 Markdown；需要源码时按快照约定人工准备 |

源码只在查询／审校需要版本检查与补证据时按 [源码准备](prepare-source.md) 处理；安装说明不要求所有人先解压游戏。
