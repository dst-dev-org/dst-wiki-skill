# 版本适配查询

判断某个模组是否需要为游戏版本更新做适配时读本文件；普通组件查询不加载。更新报告在 `K/wiki/updates/`，顶层 `index.md` 登记各报告的起止版本与审校状态。

1. **选报告**：按模组原适用版本与目标版本选起止版本匹配的报告；版本链不完整或起点不同时分别说明，不混用。
2. **读报告 index**：先适配检查清单（条件 → 动作），再本轮主题；命中即得候选结论与条目编号。
3. **匹配模组接入点**：在模组内定向搜 require／modimport、AddComponentPostInit／AddPrefabPostInit、方法覆写与包装、事件监听与派发、TUNING／控制常量、标签与状态名、原版模块引用；不默认读整个模组，不构建完整依赖图。
4. **定位条目**：用接入点符号（函数／事件／标签／常量／组件名）在对应 `detail-*.md` 定位条目行。未命中检查清单不代表无需适配，仍须按符号查明细。取得本条变化、影响条件、旧新证据和明确对应本条的审阅结论，实际接入落在所列影响或排除条件内，才可直接用于判断；不只匹配符号名。旧表／自由文本可从条目及必要相邻说明提取同等信息，不因格式或状态措辞不同重读源码。引用已有编号；无编号则给实际页面／章节，不造编号。明确待核验、证据不足／冲突或条件未覆盖时才定向补查；“无实质变化”标签或报告整体已审校不能代替条目证据。
5. **判断并输出五分类**：必须适配（命中破坏性变化）／建议调整（仍可运行，但行为或推荐接入方式变化）／所检用法兼容（已核对实际调用，旧用法保持兼容）／待核验（报告或接入信息不足）／本次范围未发现适配需求（说明实际检查范围，不扩大成整模组保证）。仅对上一步已满足复用判据的用法给确定性结论；部分用法已覆盖时分开报告，不把其余用法一并判为兼容。
6. **回查源码仅限**：报告缺失、证据不足、版本链不完整或接入方式超出记录；回查按 [查询规则](query.md#定向回查源码) 的定向搜索执行，不扫全库。

结论标注"按报告条目判断"；涉及运行时行为的结论保持对应验证程度，不因报告存在而升级为运行验证。
