# DST 知识查询

K 尚未确认时才按 [路径约定](../setup/paths.md) 定位，已确认则复用；本文件的 `wiki/`、`raw/` 均相对 K。仅查询已有内容时，不写知识页或日志。明确整理通用骨架才读 [骨架维护](../maintain/maintain-skeleton.md)，其他知识写入／检查读 [维护规范](../maintain/maintain-wiki.md)。判断模组是否需要为游戏版本更新适配时，读 [版本适配查询](read-update.md)；普通查询不加载该规则与历史更新报告。

基础查询直接搜索／读取现有 Markdown 和必要源码，不主动执行版本／来源哈希巡检或判断是否最新。用户明确要求版本核验或判断是否最新时，才读[版本维护](../maintain/maintain-version.md)；其他知识维护按对应入口执行。查询脚本与索引缓存仅作可选增强。

## 源码准备

查询直接使用已有 Wiki 和源码快照，不在会话首次核对游戏安装或运行 setup_raw。只有回查所需源码缺失时，才按[源码准备](../setup/prepare-source.md)取得必要输入；只有 Wiki 时仍可回答其已覆盖范围，不要求先安装游戏。已有快照不称为线上最新；用户明确要求核验版本时再按版本维护检查。实际解压才按[日志维护](../maintain/maintain-log.md)记录，用户指定历史快照时不更新 current。

## 证据

- 日常问答、方案探索和实现默认采用 Wiki 的现有说明。Cookbook 或机制页的示例适用于当前场景时可直接复用，遵循文档注明的前置条件、加载位置和适用范围。对适用性有具体疑问时再读验证记录。
- 技术结论给页面／章节或源码文件:行号，保留函数／状态；调用点不能替代实现审阅。sources 相对所用脚本根，历史快照引用实际路径。
- 注解、facts 与有限 resolution 仅作线索，fork reviews 只支撑已核验条目。概念性训练知识标记 `[训练数据，未核实]`。源码审阅、结构检查与游戏运行分开报告。无证据写缺口，不宣称未运行代码通过。

## 查询

### 先查 Wiki 并判断是否已足够

先按问题选择入口；路径与主题名称以知识库现有索引为准，不要求经过每层导航。已得到足够候选就直查，不补走其他定位路径：

| 问题类型 | 定位方式 |
|---|---|
| 已确认组件、接口或页面名称，问该对象的具体行为 | 匹配文件名，直查对应页／章节，跳过索引 |
| 只描述需求，尚不知组件名 | 筛页面 summary／aliases／标题，并搜索已有主题索引的需求摘要、别名和选型提示；先返回候选路径／命中行 |
| 问“哪些机制／如何选择”，或命中多个不同用途的组件 | 优先读匹配索引的选型句或分组，按作用对象、触发条件、次数／时间等缩小候选，再查必要知识章节 |
| 新增功能、造物或多文件组装 | 先从 `cookbook/index` 找适用骨架或示例，已有定位可直达；没有匹配示例或只覆盖部分需求时，按缺口查机制页 |

“已确认名称”来自用户明确提供，或已有 Wiki／源码定位。联想的组件名只作候选。中文名／俗称先匹配标题、aliases 和索引别名，多义时结合场景筛选候选。需要在游戏名和 Prefab 注册名之间转换时，定向搜索 `K/wiki/assets/prefab-names.csv`，再用命中的注册名查 Wiki 或源码。速查表的版本见同目录说明，动态名称按实际显示路径核验。已有 Prefab 页可直达“注册与构造／关联机制导航”。行为、UI、世界生成和数据消费也可在 reference/mechanisms，缺分类仍搜实际页面。

用宿主搜索或 `rg` 时，只查相关分类。主题位置已知则复用；尚不清楚时，按实际标题／行范围读分类索引的需求浏览部分，分类也未知才读 reference/index。只展开匹配主题，Top 30 不作为普通需求定位的前置；不因模型猜测名称就先读该组件全文。索引缺失继续搜真实页，断链先找现有文件，不为查询修复导航。

未知需求的首轮只筛上述页面元数据与索引条目；仍不足再定向搜知识正文，必要时读少量快速判断。只读索引命中分组与少量上下文，确需比较相邻行时再补；索引用于选页，技术结论引用所选知识页的相关章节及适用条件。候选过多则收窄措辞或主题，不展开宽泛全文、不把省略结果当无命中。组合需求拆效果、对象、条件与单位，核对持有者、同步、生命周期和清理；每轮初始候选共用最多5个，不要求一篇骨架覆盖全部。

选中页先取元数据、快速判断／适用条件和所需章节标题，再按真实行区间读目标章节，按需补读边界或验证记录。子节连同父级前提，代码连同所在文件／加载位置、完整围栏和必要清理一起读取；出现截断或仍缺条件就补区间，短页全文更省操作时可直接读全文。章节定位失败先核对实际锚点，必要时改按行区间或全文读取，不将定位失败当作内容缺失。Markdown 锚点不保证宿主裁剪，没有按行读取能力则读选中页全文，不无条件读所有候选或展开相关链接。

例如已知组件用 `rg --files "<K>/wiki/reference/components" -g 'finiteuses.md'` 精确定位；主题已定位时可用 `rg -n '耐久|寿命' "<主题索引实际路径>"` 先看命中行，再用 `rg -n '^(summary:|aliases:|## |### )' "<选中页>"` 定位章节。查询不先枚举整个 K 的文件。

**进入源码前的判断。** 接入已有模组时核对本地接入点，局部修改或排查 Bug 时先查本地实现。只有文档不足以确定方案、文档用法与实际行为不符、存在已知冲突或失效，且问题涉及原版行为时，才对疑点回查目标版本的游戏源码。用户明确要求查源码时直接定向查。

### 定向回查源码

原版行为检索限定所选 scripts 根并排除 `.po`。核验官方名称时，只在所选语言文件按名称键或译文定向查找。已知定义先直查文件；位置未知时用 `rg -l` 取候选路径，再在少量文件内用 `rg -n` 定位并读完整所需函数／分支、必要调用与宿主。禁止对整个 scripts 或 prefabs／components 分类展开泛关键词正文及上下文；先返回路径、选定文件，再读实现。

已明确通用门禁或处理路径时，不枚举全部消费者／实例；只有本题依赖特定对象差异时才查该对象。无命中／歧义／截断或不可读文件不证明没有实现，补足当前缺口后停止。缺少必要源码时，说明未核验项并先给可确认的部分或待核验方案。

### 输出前检查

给出本题结论、依据及未核验范围；代码沿用实际加载环境。生成／修改模组入口，或需判断 GLOBAL／名称可见性时，按需读 `K/wiki/cookbook/mod-starter.md#全局名称与加载环境`；已有同会话有效结论则复用。

已定位的工具箱 `dst-toolbox` 及 Python 可用时，按需读 [Wiki 查询脚本 query_wiki.py](search-wiki.md) 或 [源码索引查询脚本 source_index.py](query-source.md)。不默认读日志、维护规范、模板、全部 Wiki／AST／JSON，不自动展开无关链接；复用同会话未变化内容。
