# DST Wiki 版本增量维护

仅用户要求版本／改动复查时读取，普通查询不触发。K 未确认才按[路径约定](../setup/paths.md)定位，已有结果复用；游戏源码和输入模组只读。

本次维护（本轮）指同一请求范围与旧新快照下的复查，可跨会话继续；批次是其中一组明确页面，阶段收尾指请求范围全部处理后的最终核对。会话仅是上下文复用边界，不是全检触发器；换会话／进入下一批不单独触发全检，复用结果前须确认输入、覆盖范围及相关文件未变化。

## 版本入口与范围筛选

1. 确认目标页面／主题、目标快照及是否允许修改。需要跨页统一筛选、批量沿用或集中基线收尾时，再读[批量协议](maintain-version-batch.md)；独立逐页修补沿用本流程，不按页数决定，也不因存在关联链接自动扩大任务。
2. 用所选 scripts 父级 BUILD.txt 确认输入；Steam 纯数字记为 `steam-buildid:<值>`，其他编号保留体系，不比大小猜新旧。页面 dst_build、游戏版本和 Git revision 不互换。只有明确跟进本机游戏时才按[源码准备](../setup/prepare-source.md)核对安装。
3. 先看请求页的 dst_build／status／sources，默认处理 active／review-needed；archived 仅按请求复查。同版本且无已知失效时跳过版本迁移；版本落后／已知问题仍需处理，不因源码本次未更新而漏掉。未知／不同编号体系不自动升版。

## 确定旧／新基线

游戏旧输入按页面版本查已知 raw/archive 快照并核对 BUILD；目录名不证明证据一致，同版本多快照须结合已有哈希／锚点确认。当前输入使用本次选定 scripts，不展开全部历史源码。缺旧输入时可核验当前实现，但注明“无旧基线，未完成版本对比”。

有明确源码 Git revisions 时可比较，否则只对必要文件用 `git diff --no-index --ignore-cr-at-eol`（退出 1 是有差异，2 及以上是错误）。模组改动用用户指定 revisions／工作区差异；Wiki Git 只辅助旧结论／引用追溯，不代替游戏差异，不 checkout／reset 现有改动，源码不入远程。

获准写入的游戏跨版本维护，确认起止版本后默认按[报告增补](write-update.md#随知识修补增补)建立或复用对应报告，随后随知识页修订逐批扩充；不以完整报告为修页前置。仅检查、同版本修补或模组改动不强制新建游戏版本报告。

## 更新条目复用

先确认 K/wiki/updates/index.md 的起止版本和快照，按所选页文件／接口／事件／标签检索对应 detail，只读命中项。本条变化、影响条件、旧新证据及明确对应本条的审阅结论齐全，且无已知证据失效／冲突时，将当前页引用及必要案例的调用／hook／监听方式，与条目所列参数、对象、主客端、触发阶段等相关条件逐项匹配；当前用法须落在明确记录的影响或排除范围内，符号同名不算覆盖。匹配则直接复用对应条件下的结论，只覆盖部分用法就只复用该部分。

新格式按五字段读取；旧表或自由文本可从条目及必要相邻说明提取同等信息，不因缺列、编号缺失或状态措辞不同而回查源码，也不为读取改写报告。仅有“已核验”“无实质变化”等标签或 index 总体审校状态仍不够；明确待核验、证据不足／冲突、条件不匹配或范围不明时，才对缺口读相关 diff／必要实现。不得靠改写措辞把待核验内容变成已核验；报告未命中不证明无变化。

得到新结论／条件／纠错时，按[报告增补](write-update.md#随知识修补增补)同批回写并关联实际修订页；只复用已有条目不重复扩写。纯行号映射留 output，机械沿用按下方收尾记录。

## 核验影响与局部修订

1. 需要改正文时先读该页全文；源码只读与结论／demo 有关的 diff、分支和必要调用。定义未变也考虑已知消费者、宿主／事件、配置及调用条件变化，复用已有判断，缺口才补查；不展开完整调用图。
2. 按[查询证据](../query/query.md#证据)处理实际变化；词汇命中与机器定位不证明语义或动态依赖完整。

| 变化 | 局部处理 |
|---|---|
| 仅行号／位置变化 | 可用[锚点迁移预览](verify-wiki.md#源码锚点迁移)定位；歧义、上下文不足或跨文件迁移只补查命中处，不逐锚点重读无关源码，匹配不证明函数身份 |
| 实现／接口／副作用改变 | 按适用条件修结论与必要 demo，核对同步、生命周期、清理和存档；结论仍成立则保留，不为 diff 重写全页 |
| 证据删除、冲突或不足 | 标明对应缺口，不继续推荐，状态按任务入口的权威规则处理；删除主题先查入链、迁移有价值部分并修复导航，原路径保留去向或原因，不静默删除 |
| 路径大小写变化 | 引用改为快照实际名称，并核对所用行为及 require 接入；定位修好不代表内容已复核 |

3. 只检查真实依赖变化结论的入链／骨架，以及 sources 指向变化文件的必要关联页；保留有效经验，机制正文只维护一份。范围外问题列待查，不自动扩成批量或创建计划页。
4. 写机制／索引时追加[知识维护](maintain-wiki.md)，写 cookbook 时追加[骨架维护](maintain-skeleton.md)，已读规则复用。沿用字段与结构时不读模板／格式全文；需改约定或重组再追加。只要求检查则报告问题，不改页。

## 完成与停止

仅当本页用于指导实现的关键结论／demo 在目标版本均核验或有充分沿用依据，才更新 dst_build／updated；部分复核保留页级版本，逐项注明覆盖及缺口。旧审阅／运行记录保留原 build，不继承 `runtime-tested`。结论修订处注明目标版本和新证据；旧证据用真实可用归档，无旧输入不造历史链接。

按[维护校验](verify-wiki.md#按变更选择)只查本页及实际改动；必要基线处理见[哈希入口](verify-wiki.md#源码哈希基线)，仅建立缺失条目、来源集合变化、已核验原始字节变化或归档移除时处理，未核验页保留原基线，不因改日期重复刷新。游戏跨版本维护的纯机械沿用集中简记到报告的[Wiki 沿用记录](write-update.md#wiki-沿用记录)，页内链接共享依据；其他修补可在页内简记。有结论修订才补详细条目，每批收尾同步报告实际覆盖／待查范围，再按日志规则简记操作。

报告目标版本、已修／待查及缺旧基线；无变化且无新验证记录不刷新日期／版本／日志；无差异的页不逐页重读，也不按页面类别另设“新版复查”backlog，更新报告已覆盖的条目直接复用、旧审阅记录保留原 build。证据不足不标已复核；工具不可用可定向人工核验并说明未检项，不安装环境、重建 AST／全量索引或后台监测，不自动提交／推送。
