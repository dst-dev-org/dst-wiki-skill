# DST Wiki 源码类型选择

仅新建／重组且页面归属不明，或生成非组件页时读；分类已明确的组件页直用组件模板。目录约束、模板映射及共用元数据、标签与大小只在 [页面格式](write-format.md)，证据／写入在 [知识维护](maintain-wiki.md)。本文件只管主题选型与类型差异，不加入日常查询链。

先看声明／返回、加载入口、实际消费者与宿主，再选择主题；目录名只是线索。一文件可支持多个主题，一主题可引用多个文件，不要求一文件一页。

选型只需下表；生成时追加对应小节，不默认加载所有类型差异或全部模板。

| 页面主要回答什么 | type | 选型差异 |
|---|---|---|
| 可挂载组件的职责、接口与协作 | `component` | Replica／helper 随实际关系归属，不从路径猜组件 |
| 一个原版实体／同族的工厂与组装入口 | `prefab` | [关系导航](#prefab) |
| StateGraph 的状态执行与动作／事件接入 | `stategraph` | [SG 差异](#stategraph) |
| 对模组开放的调用、注册／Hook、宿主接口或配置约定 | `api` | [API 差异](#api)；组件方法仍归组件页 |
| Brain／行为节点、UI、世界生成内部机制、配置／数据消费者或其他模块协作 | `mechanism` | 按需读下方对应小节，主题可用 `ai`／`ui`／`worldgen`／`data` |
| 跨文件创建新物品／角色／建筑等的可复用工程骨架 | `cookbook` | 单文件机制说明不自动成为骨架 |

先复用现有主题，只有存在已核验内容才建分类／叶级导航。数据跟主要消费者归属：组件参数留组件页，布局内部流程归 worldgen，公共注册协议归 API；跨机制共用的数据主题才独立。同一结论保留一个主要页面，其他类别链接它，不因为引用多个目录就多建页。

## Prefab

- 名称与检索：文件名保留实际注册名，玩家可见对象以已核验的简中游戏名为主，单对象页用“官方中文名（注册名）”；族页可用主题标题，主要对象的游戏名放在摘要、正文首次介绍及索引入口。描述与俗称用于补充说明和检索；无译名的内部对象可用“已核验的中文效果描述（注册名）”并注明不是官方译名，无合适描述则保留注册名。按同版本原版简中实显或源码的实际显示路径核名。Lua 覆盖、动态拼名和界面字符串按各自来源核对。`.po` 查实际键的译文，`strings.pot` 的空 `msgstr` 不能证明缺译。在“注册与构造”或“验证记录”简记名称键或实显条件及证据。实际用于核验本页名称的 `.po` 计入 `sources` 并保留正文证据锚点，其文件变化表示名称依据待复核，不等同 Lua 机制改变。aliases 收录注册名、已核验中文名／效果描述、必要需求措辞及用户明确提供或有可靠依据的常见俗称／旧称，不编造或穷举叫法；标题、别名随原条目同步到索引。本页负责的注册名写入 aliases 与正文，一个注册名只保留一个主要知识页，其他页可引用；俗称、需求措辞允许跨页重叠，不要求全部 aliases 全局唯一。
- 核验实际返回的注册名、包装工厂和共同／专属初始化。运行时形态切换列出条件。有同版本注册清单时，按注册名核对本批归属与共享工厂的剩余项，覆盖以主页正文为准。Prefab 页是原版实现入口，造物查询优先 cookbook。
- 关联导航列清已核验工厂的直接组件，包括 helper／动态挂载或移除；再列实际 Replica／同步、SG／Brain、关键 API／事件／数据消费者、关联 Prefab 与必要资源。每条给用途、关键配置、变体／端／阶段、已有 Wiki 具体章节及关系证据；只展开一层，不复制机制正文。跨文件核验以确认当前关系的实际行为、条件及必要清理为止；目标内部机制归目标页，未展开部分注明范围，不因新依赖自动扩展任务。
- 区分挂载、调用、监听、消费者、生成／掉落和仅资源／依赖声明。标签效果须查消费端，`prefabs` 数组不证明生成，`require` 不证明安装了 Brain，同名文件不证明 Replica。父子与清理分别核验 Lua `children` 登记、引擎父子关系、Follower／跟随关系与实际清理对象；区分宿主实体、网络代理、本地动画三类角色，不能仅凭 `SetParent` 推断随父删除或“无自身清理”。缺页用实际源码入口并标“Wiki 待建”，不造悬空 Wiki 链接；未核验关系保留范围说明。新页落地后，按其实际注册名定向反查已有 Prefab 页的待建关系，核验后补 Wiki 链接并更新对应待办。
- 皮肤差异归本体页，在关联导航按需列“皮肤／条件 → 额外组件或 Prefab → 生成与清理 → 入口”；已核验的显著可见效果（如雪花、花瓣）写入对应条目，必要时纳入摘要／aliases 与索引检索措辞，不凭名称猜外观。仅换贴图可合并说明，不默认独立建皮肤页或集中全库皮肤。附属 FX 可同页简述或留源码入口，确有独立行为／复用需求或超预算再拆；影响主要能力的独立生成物优先与主体同批建页并互链，各自维护行为。俗称重叠时在摘要／索引区分施法物品与产物；一层导航不限制同批建齐关联对象。
- 同族变体优先入表，同一转换链的形态优先同页对照。定页时把决定主要获取或转换方式的植株、生物或设施优先纳入同批（如牛毛与皮弗娄牛），已有页则复用，次要来源简列。用途或查询入口明显不同的关联对象可拆页，拆后互链并核对共用的转换和产出条件。共用机制链接主要页，各页保留自身差异与必要接入条件，不为形式预建协议页。关联多时按类别分小节，同条件条目可合并。超页面上限先精简，再将确需拆出的工厂／关联主题页仍置 `prefabs` 归属并互链，不默删关系或在根索引展开全清单。无需默认跟读所有关联页。
- 建页收尾每批选少量实际需求，用当前 Markdown 的标题、摘要、aliases／索引筛选并读取目标章节，核对能定位所需内容、区分主体／产物；遗漏回补检索措辞或范围说明。此项不依赖查询缓存或向量库，不将结构校验通过当作检索验收。

## StateGraph

- “关键流程”只选需求涉及的 ActionHandler／EventHandler → 状态 → onenter／timeline／timeout → 跳转／onexit；给 tags、目标条件、帧与秒的单位、打断／失败／清理及证据，不抄全图。
- 核对 Prefab 宿主和实际加载名；区分实体 tags 与 state tags、全局事件与状态事件，公共状态 helper 须核验真正生成的状态。需要预测时分别查服务端与客户端图，不能把某生物 SG 的写法当通用玩家预测方案。

## Brain 与行为节点

- 归 `mechanisms/ai/`，说明 Brain／BT 的决策与 SG 的动作执行分工，链接已核验宿主。Brain 的 require、安装与启动是不同证据。
- “关键流程”记节点顺序／优先级、判定条件、重评周期、READY／RUNNING／SUCCESS／FAILED 和中断／停止；仅保留影响本需求的分支。接口表用于节点构造参数／回调，不把节点名当组件方法；核验调度器、节点实现和必要动作／locomotor／SG 消费者。

## API

- 核验调用环境（GLOBAL、mod env、返回模块或实例）、签名／返回、注册键、加载顺序、回调对象／参数，以及注册后真正执行的位置；内部 local 函数不能直接写成模组可调用 API。
- Hook 说明覆盖／追加／包装、重复注册与冲突边界；runtime、worldgen、frontend 的接口可用范围分别核验。data-only 的公共配置协议可用数据约束表，不强造函数。

## UI

- 归 `mechanisms/ui/`，说明 Class／返回值、父节点挂载、实际创建宿主、输入／焦点、更新及 Kill／清理；区分 frontend／HUD／其他客户端环境。
- 显示数据追到来源与更新通知；发起游戏操作须另核验服务端处理。不能仅因是 widget 就假定玩家／TheWorld 存在，也不能把 UI 对象的 inst 当联网游戏实体；资源声明与资源实际可用分别记录。

## 世界生成与运行时场景

- 世界生成内部流程归 `mechanisms/worldgen/`；运行时 scenario 按实际机制主题归属。追踪定义、注册／装配与消费者，核验执行阶段、地表／洞穴及重试／随机边界。涉及世界布点时，区分布局定义、注册、抽取／放置和实际生成，落点或频率未核验时注明。不从 map／scenarios 路径认定环境。
- 数据表记被读取的字段、单位／可选值、默认与组合约束；公开 AddRoom／AddTask 等接口归 API 并互链。核验 modworldgenmain／modmain 的可用环境和资源加载，生成阶段示例不套 runtime 实体组件操作。

## 配置／数据与其他模块

- 常量表／配置／工具模块先追实际消费者，说明读取时机、快照／实时读取、作用范围与修改入口；不要把某处默认值当完整类型或有效范围。
- 只有独立复用需求才建 `mechanisms/data/` 或其他具体主题；不为全部 util／tools／languages 建页，`.po` 仅按需核验名称，不另建机制页。未找到加载／消费者时留缺口，不生成声称可用的接入代码。
