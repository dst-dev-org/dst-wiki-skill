# DST Wiki 索引维护

仅组织／拆分索引、检查层级／登记完整性或明确维护查询缓存时读取。普通内容修改只更新原叶级条目与必要链接，无需加载本文件。证据与写入步骤见 [知识维护](maintain-wiki.md)。

## 索引格式

索引页 frontmatter 使用 `title / created / updated / type: index / tags: [overview]`，不填游戏核验字段。

| 层级 | 内容 |
|---|---|
| 根导航 | cookbook／reference 两类入口＋Top 30 高频快捷入口；不扩展为全量列表，不纳入工程文档 |
| 分类／主题索引 | 主题范围与子索引；小分类可以直接列知识页 |
| 叶级索引 | `入口 \| 需求摘要 \| 必要别名/状态` |

索引文件大小遵守 [页面大小上限](write-format.md#文件大小)，含 Top 30 在内，不在本文件重复数值。

## Top 30 高频入口

仅明确要求快捷入口整理，或索引 Lint 发现需要调整时维护；普通新页 Ingest 不评选新增项，已有入口的失效／迁移修复仍随本次修改完成。

根导航最多收录 30 条已存在的 active 技术页或章节（可含 cookbook），每条一行“需求 → Wiki 链接”，不放代码、签名或长说明。它只是所属叶级登记之外的快捷链接，同一目标去重，不要求凑满 30；不是查询的必读前置或默认 30 个检索候选。

无统计时按真实开发需求人工精选，注明依据与维护日期；有实际查询／任务记录时注明统计范围与日期，不把源码引用次数或模型猜测称为查询频率。页面过期、待复查、归档、删除或迁移时同步移除／替换快捷入口及链接，不隐藏状态；已知名称继续直查。

## 登记与拆分

- 每页在所属叶级索引登记一次；同一分类索引可登记本目录的独立页并路由到子主题，子目录页面在自己的叶级登记，不重复列到父级。摘要、别名或状态变化时同步条目。有真实关系时允许跨主题互链，不复制实现。
- 条目增长使筛选困难或单次读取过大时，按真实需求拆主题，不预建空层级。叶级索引约 60 条或 12 KiB 时先评估主题是否可分离；确实可分成两个稳定主题才拆，拆后更新父级入口、页尾返回链接和旧链接，按 [维护校验](verify-wiki.md#按变更选择) 检查遗漏、重复登记、悬空链接与无入口页面。不要仅为压到字节上限把同一机制族拆成碎片页。新建或拆分页的返回链指向其登记叶索引；允许另保留分类 hub 链；历史页不为统一形式批量迁移。
- 已知名称可绕过导航；需求检索先筛摘要、别名和标识符，再读少量候选章节，不要求全量读取大分类索引。
- reference 导航列已落地内容的 components／prefabs／stategraphs／api／mechanisms；首篇有效内容落地且分类索引不存在时，创建对应分类的 `index.md`，在其表格登记页面，并在 `reference/index.md` 的分类表中链接该索引，不直接登记知识页。API 与 mechanisms 的多页主题按需要建短索引，不预建空分类或多层子索引。每页在所属分类的一个叶级登记，跨分类关系用正文互链；Prefab 内关联机制表是关系导航，不是其他分类的叶级登记，新增层级不成为查询必读步骤。
- cookbook 首份已核验骨架落地时再建分类索引并补根入口；该索引只列任务、适用范围与状态，不嵌 demo。新增内容定向读对应骨架和必要机制链接，机制查询／修改已有内容不必经过它；索引不登记尚未写成的计划页。
- 源码符号索引与精选知识索引分别维护；知识候选不默认纳入日志、会话、项目决策、模板、AST 或未审校注解，也不因全量源码解析自动建页。

只有调整索引设计时，才按知识库实际路径读 `K/docs/decisions/layered-index-and-retrieval.md`；日常登记／分类整理使用本文件即可。

分类／子主题入口与叶级登记用 Markdown 表格，返回父级、跨主题互链用正文链接；归档页可移出正常导航，历史查询仍可搜到。

## 可选查询缓存重建

仅在明确的索引／缓存维护任务中，需要重建查询缓存时执行。已配置工具箱和 Python 可用时，将 K／S／T 替换为实际绝对路径：

```powershell
python "<T>/scripts/tools/wiki/update_index.py" --wiki-root "<K>/wiki" --format "<S>/references/maintain/write-format.md"
```

工具先检查页面及导航，通过后才生成默认缓存 `K/output/wiki/index.json`；独立校验沿用“登记与拆分”中的维护校验入口。人工 Markdown 是分类与摘要的维护来源，工具不自动重排／覆盖导航、重写摘要或根 Top 30。缓存是 Git 忽略的可重建产物，不替代人工知识页；工具不可用时仍可人工维护导航并直接查询 Markdown。查询工具按需读 [Wiki 查询](../query/search-wiki.md)，不读取整份缓存。
