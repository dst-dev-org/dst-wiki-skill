# 源码知识页复审派发模板

仅实际派发或执行独立源码复审时读取；主代理自查、已有页增修与普通查询不加载。复审执行既有维护规范，本模板只列本批重点与输出格式，不另立标准。

## 派发前确认

- 给出页面路径、源码根与实际 build、本批范围（页／注册）以及已知风险：新页、混合载体、事件数据包、尺寸临界、近期改动。
- 默认只读。明确授权 `review+fix` 时列出可修页面。有疑点先核对源码，结构校验通过不能代替技术核验。

## 可直接填写的任务文本

```text
任务：独立复审下列知识页（修订授权：<无／列明可修页面>），按源码事实给出 P1（事实错误／危险误导）、P2（精度／边界／页内与索引一致性）、P3（体例）。
K／S／T：<绝对路径>
build：<实际编号体系:版本>
待复审页面：<页面绝对路径；必要时列行数／字节与档位>
本批对象与范围：<注册名／接口／待核验行为>
源码根：<绝对路径>
源码入口（可选）：<实际文件或符号>
共享规则表（可选）：<本批规则表及涉及页和索引行，或“无”>
防复发检查（可选）：<本批相关的旧错触发条件／反例及记录位置，或“无”>

首次独立复审按下列顺序执行。事实依据用同版源码或适用的同版实测。页面表述、共享规则表、作者清单与旧报告只作对照或补查线索。

1. 核对页内断言。先按对象从实际注册、实现与必要调用方自建事实骨架，记录源码位置、成立条件与例外。再对照各页查遗漏条件、矛盾结论与范围差异。只选本批相关重点。
   - 时序与端：核对调用顺序和当时的状态、主模拟／客户端、专服／非专服分支。涉及存档时追构造、postinit 与读档恢复顺序。
   - 可达性与生成：确认组件、SG、Brain、回调实际接入，检查门禁、注释与提前返回。追 SpawnPrefab／GetPooledFx／SpawnChild／ReplacePrefab 等实际调用与动态拼名。依赖表、注释和图鉴只作定位线索。依赖搜索的否定结论写明检索范围。
   - 对象与清理：区分宿主、网络代理与本地动画。分别核验 Lua children、引擎父子关系与跟随关系，确认实际清理对象。混合载体区分玩法结算与 FX 表现。
   - 名称与格式。新 Prefab 或主名称变更时，按原版简中实显或显示路径核对标题、摘要、正文首次介绍及受影响索引，可用「Prefab 译名定位」辅助。尺寸和锚点按任务范围与现行规范核对。
2. 核对跨页一致性。对照共享规则表或实际发现的跨页断言。同版且条件相同的公共链只核一次源，逐页检查实际接入与例外。按事实回扫摘要、正文、导航表、关联页、索引和当前交付记录，核对条件与结论。
3. 反向扫并追到消费端。补查骨架漏掉的绝对句、「先…再…」和否定断言，可用作者清单或旧报告定位。命中防复发检查时，按本版源码核对反例在正文和示例验收中的实际结果。关键结算、时序、端与门禁的断言追完整链。多页批次再优先抽每页两条尚未贯通的高风险链，候选不足时按实际覆盖。区分逐项核验、抽样和未核验范围。

修订后的复验可复用同版且证据仍有效的骨架，只重查受影响条目与调用链。同一事实仍有冲突时记为部分修复。

输出一份可直接交修的检视报告。一致项可按「骨架条目｜依据与条件｜页面命中」合并。差异按事实归并为 P1/P2/P3，每条列影响、源码位置、成立条件及适用反例、所有受影响的页和行号、修法与验收条件，标明可直改和需主代理同步的位置。给出总体结论「可验收／需修复」，注明验证范围与是否运行游戏。
```

## 收口

处置 P1/P2 前按锚点回源码复核，有出入时记差异与依据。获授权直修时仅修指定页的已核实问题，优先替换原句，回读改后表述并定向校验。修订回执按事实回扫摘要、快速判断、正文、导航表、陷阱、验证记录、关联页与索引行。逐处列位置及「已同步／待主代理同步」，无命中的检查项标「无命中」，附实际自验结果。缺回执或仍有待同步位置的条目保持待验收。主代理处理其余修订、索引、record 和日志。
