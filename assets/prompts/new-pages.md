# 新建知识页任务派发模板

仅实际派发或交接新建源码知识页时读取。已有页增修、查询及自行完成新页不加载。页面结构、证据和校验沿用知识维护规则。

## 派发前确认

在相关分类定向确认已有主题、目标路径及任务占用，避免重复建页或重叠写入。已有覆盖优先复用。确认所选 scripts、版本与必要源码入口可读，再将互斥的新页清单分组。Prefab 分组按 [类型指引](../../references/maintain/source-types.md#prefab) 一起确认主要关联对象的归属。

同批多页共用技术断言时，整理共享规则表，随派发与交付传递。每条指定主章节，列出涉及的页和索引行，证据未齐的条目标待核验。

有相关历史检视时，按本批实际复用的机制定向选取仍适用的失败条件或反例。共用检查写进共享规则表，单页检查写进对应派单。优先选能改变写法或验收的检查，例如禁用时是否仍处理已到期事件、清状态与结算的先后、示例对无效对象或旧存档的实际行为。只传命中项及出处，旧报告作定位线索，当前结论按本轮源码核验。

派单里附两条命令、不要混成一条：**派发方的页面校验**（含 venv Python 与 `--wiki-root`／`--format`／`--source-root`，`--wiki-root` 指 `wiki` 目录本身）随派单给出，作为本批尺寸与链接数字的依据；执行方不跑这项校验，大小按 write-format 自查；**执行方的源码引用自查**只有 `validate_source_links.py --strict` 一项，参数仅 `--wiki-root` 与页面路径。每页的目标叶索引随清单写死，不让执行方按目录名推断归属。

切组按读取代价而非题材：相邻页的候选关系用工具箱 `group_pages.py` 给出（判据是共引稀有链接或共引非样板 source，通用接口如 `stackable` 不算依据），它只出候选、不判断语义。同轮页集合须由批次目标与验收分组决定，工具结果不能直接当派单分组。

派单前按下列顺序取证据，每一步都不重复前一步已给出的结论：
1. `query_wiki.py search`（工具箱 `wiki`）按页名／别名／需求措辞确认真实落点与已有覆盖，命中页直接给路径，不让执行方重新搜。
2. `group_pages.py` 给出同轮候选与单向链接缺口。
3. 每个源码入口先查 `K/wiki/reference/` 是否已有对应知识页（组件、StateGraph、API 同此）：有且 `dst_build` 与本批一致 → 派单写明「语义读该页，只有宿主侧接入顺序要回源」；有但基线落后 → 按 `updates/` 对应条目核对；没有 → 才允许通读源码。
4. 仅在上述三步都缺时，才按 `source_index.py query` 定位符号区间。

## 可直接填写的任务文本

替换必要占位符，可选信息没有则填“无”；路径采用实际值。

```text
任务：生成下列新知识页，完成后交派发方验收。
K（知识根）：<绝对路径>
S（知识 Skill 根）：<绝对路径>
T（可选工具箱）：<绝对路径；不可用则注明>
所选 scripts 根／版本：<绝对路径及实际编号体系:版本>
新页清单：<主题｜目标路径（相对 K/wiki）｜type｜本页范围｜注册名（逐字取首个 Prefab(…) 实参）与 file:line｜是否共享章节｜目标叶索引；可选大小档>
源码入口：<实际文件／符号；允许按证据需要定向补查必要实现与消费者>
共用／复用入口：<已有入口或本批承接页的页#章节及范围，或“无”>
共享规则表（按需）：<断言及适用条件｜同版源码链｜主章节｜涉及页与索引行，或“无”>
防复发检查（按需）：<仅本组相关的旧错触发条件／反例及其记录位置，或“无”>

按 S/references/maintain/maintain-wiki.md 的 Ingest 及其指定的通用要求执行；规则、模板、校验与检索一律用 Skill 与工具箱已提供的脚本，不另写临时统计脚本、不复制已有实现、不改动 raw 快照；缺少所需能力时在回执报告缺口，不自行造工具。

从页面格式选择已有的一份内容模板，非组件／归属不明时才追加类型指引。
按页面格式的复杂度与大小预算写作，不按源码总行数扩额；非默认档按规则标注。验证记录只写核验范围、未覆盖项与运行状态，不追加修订过程；选档理由、结构／链接校验结论、行数／字节／锚点数、修订轮次与 R／P 编号一律写进交付回报，不写进页面（数字写进页面还会随自身长度漂移）。
按符号定位取证据：优先 source_index 查询（prefab／component／call），索引未建时用 grep 限定单文件或子目录，不整文件通读后再筛行。
检查源码锚点首尾及证据范围，确认有效内容支持结论；结构行警告结合上下文复查。
工具调用整体失败且拿不到可用错误信息时，降级为单文件单区间读取重试最多两次，仍失败记为未核验并在回执注明，不静默停止。
此前批次的记录与预核结论只作待验线索，不能替代源码证据；
与实际实现不符时按证据写页，并返回勘误建议，已有有效核验依据仍可按原规则复用。
对共享规则引用主章节，写明本页如何接入及有何例外。发现出入时按源码提出更正，列出需要同步的页和索引行。
交稿前用派发的反例检查相关断言及示例验收，确认示例实际执行的分支与验收预期一致。
只创建本批指定新页；目标已存在、已有同主题覆盖或出现并发写入时，
返回命中与增修建议，交派发方调整，不覆盖已有页或另造重复页。
缺必要路径／源码／证据时返回受影响页和缺口，不猜版本，不扩库补齐所有依赖；
尚无 Wiki 的必要依据可引用实际源码，不建立空页或悬空链接。
交付前跑 `validate_source_links.py --strict` 自查本页新增／改动的源码引用。判据是 0 error。新增／改动引用的 warning 修到通过，存量 warning 按引用意图判断并在回执点明（脚本检查整页）。有新增或改动的完整 Lua 示例时，按 S/references/maintain/verify-wiki.md 的「Lua 示例」自验并记录范围。页面／导航、哈希基线、覆盖自查与索引登记由派发方统一处理，格式与大小按 write-format 自查。
共享索引、日志与 source-baseline.json 由派发方统一处理；
必要互链与关联页增修以建议返回，不自动修改本批之外的页面。

按页返回：路径与实际尺寸／档位｜关键断言清单（源码位置、成立条件与未覆盖范围）｜实际检查／未检项｜
索引草案（一句摘要＋检索措辞，保留影响结论的条件）｜存疑或阻塞｜既有记录勘误与复用／互链建议。无对应事项简记“无”。
在已有关键断言清单中标出优先复审的条目，附受影响的摘要、正文和索引草案位置。按事实合并重复表述，优先标可执行示例、强断言、决定结果的条件与时序、存读档或掉落分支及共用规则。
涉及注册、生成或名称时，补本页负责的注册名、生成入口／检索缺口及名称核验结果。
在回执首行报「本组工作量当量」：按独立页计约几页。折算系数固定为——承载共享规则主章节 +2 页，每处跨页共用断言 +1 页，单个超过 2,000 行的源码文件通读 +1 页，同厂多注册族（≥5 注册）额外 +1 页；派发方下批按当量而非页数分配。
交付表示新页待派发方验收，不声称尚未执行的索引登记、record 或游戏运行已完成，
也不为交接增加 frontmatter 字段或自造状态值。
```

## 派发方验收

项目有批次分工与复审要求时，按项目约定执行，并按实际范围选取[源码复审模板](source-review.md)对应部分。交修附对应检视意见和[修订回执要求](source-review.md#收口)，复验可复用仍有效的同版证据。

核对交付与分派清单，按既有流程审阅内容并检查新页及实际受影响入口。定向检查本批新页涉及的待建关系，核验后回填互链。核对执行方的索引草案与目标页，去重合并后统一登记叶级索引。需要压缩时回查原断言及成立条件。记录必要基线并追加日志，复核后的既有记录勘误当批回写。证据不足的部分按原规则保留缺口；不因接收新页对已有页面逐页复查或刷新基线。
