# DST Wiki Skill 工程设计

最后更新：2026-11-01。目标是独立安装后以少量读取完成共享查询、生成／增修、骨架整理和检查；详细验收进度在 [PLAN](../PLAN.md)。本文件用于维护 Skill 包，日常调用不加载。

## 包内与外部资产

SKILL.md 只保留意图选择与必要公共边界；references/setup、query、maintain 分别存定位与准备、查询、知识维护规则，assets 仅承载实际生成需要的模板。职责目录不增 README／index，入口直接链接实际文件。定位与轻量源码准备 helper 可独立执行；Wiki、raw 和 output 经外部明确知识根定位，可选工具箱通过显式参数或配置使用。普通操作直接 Markdown＋定向源码，不依赖模组开发 Skill `dst-mod-dev-skill` 或工程环境。

README 维护安装和本包开发说明，PLAN 维护使用闭环与分发工作，本设计维护包职责及技术边界；知识内容覆盖只在知识仓，工具实现／版本／正式类型审校只在工具箱及 fork。跨仓总体关系由知识仓 docs/design.md 记录，本包不依赖读取该文件。

## 源码类型与模板覆盖

2026-10-14 补齐 Prefab 与通用机制模板，组件模板原文保留。目录约束与类型到模板的映射归 write-format，模板是结构实例；source-types 只维护主题选型与类型差异，不复制目录／模板表。新建／重组页只选一份模板；非组件或归属不明时才追加类型差异，已明确组件不因此多读一份文档。骨架维护沿用原页，新建／重组才追加结构规则，查询和已有案例增修不默认读。格式、证据、验证与大小规则仍只有一个维护来源，不按源码目录复制整套模板。

源码知识页按页面覆盖的机制复杂度选大小档，阈值与选档规则只在 write-format 的“文件大小”维护。可选 size_class 仅非默认档需标注，未标注的现有页仍按标准档校验；导航和 cookbook 保持各自预算。校验及索引构建共用工具箱的同一解析逻辑，不按 sources 总行数扩额，不强制旧页补字段或重写；复杂页仍按章节查询，不增加默认输出预算。

Prefab 页承载原版工厂／组装入口：注册与构造、关联机制导航给实际组件（含 helper／动态挂载）、Replica／同步、SG／Brain、关键 API／数据、关联 Prefab 与资源的用途、条件和证据；已有机制链接具体章节，缺页回到源码并标待建。关系只展开一层，不复制目标正文；造物默认从 cookbook 起，明确原版参照可直达 Prefab，查询不跟读整张关系表。

StateGraph、公共 API 使用机制模板，按需求选择接口／数据约束或关键流程；新增 mechanism → reference/mechanisms，按实际用途容纳 ai／ui／worldgen／data 等内部机制。分类由职责、入口与消费者决定，不机械一文件一页；公共注册协议仍归 API，组件自身接口留组件页。dst-wiki-skill 与 dst-mod-dev-skill 的查询、索引规则和工具箱类型映射已同步，未创建正式空分类或新知识页。代表源码与隔离草稿检视范围见 [模板检视](reports/source-templates.md)；任务级完整生成与独立模型／游戏验证继续按 PLAN 分开验收。

## 读取路径

所需路径尚未确认时才读 setup/paths，保留路径优先级、占位符、目录约定与条件入口；调用处使用条件指针，K／S／T 的复用及重查条件统一由该文件维护，S 按当前 Skill 包区分。配置示例、定位工具与异常处理、首次建库细节移至 setup/first-use 对应小节，历史快照参数和源码状态解释归 setup/prepare-source，均按需读取。源码准备不作为安装前置。仅初始化空库直达 setup/first-use 的建库小节，无需先读 maintain-wiki；同时要求生成技术内容时，再执行 Ingest。查询直达 query/query，模组经验提炼直达 maintain/extract-mod，已有核验记录的骨架增补直达 maintain/maintain-skeleton，版本复查直达 maintain/maintain-version，生成／检查直达 maintain/maintain-wiki；格式、索引、模板和可选工具参考按实际任务追加，不展开全部链接。

显式 K／T 或保存／切换默认路径的配置处理由 SKILL.md 直接链接 setup/first-use 的保存配置小节，避免路径已确认时跳过该入口；保存条件仍只在该小节维护。同会话相同路径的定位结果可复用，用户明确要求保存或切换时仍按该小节处理；独立首查复验按 PLAN 待办执行。

生成／检查分别直达 maintain-wiki 的 Ingest／Lint 锚点；两节显式指向本文件的通用要求与按任务追加，公共前置不依赖顺带读取文首。追加表按任务选择，不展开全部链接，同会话已读规则复用。

新建源码知识页仅在实际派发／交接时追加 assets/prompts/new-pages，复用现有格式／内容模板及证据规则；工作组只写互斥新页，主代理统一验收与共享索引／日志／基线收尾。已有页增修不加载该资产，不因新页交付扩大已有页复查范围，也不新增知识页字段或默认入口。

maintain-wiki 的规范入口集中到追加表，步骤只引用入口名称；源码哈希的独立职责指针、大小／章节等不同读取范围仍保留精确锚点，同级任务由 SKILL 路由。模板复用已加载规则，也保留单独查看时可按需补查的格式／类型指针；可选查询工具无需回跳已加载的查询主流程。链接不要求形成无环图，按读取用途保留必要入口，Ingest／Lint 的本文件前置指针同样保留。工程统计按 README 的维护说明，仅作专项检视快照，不形成日常记账任务。

写入收尾与 Wiki 检查进入 maintain/verify-wiki 的选择表，只保留常用命令、关注结果与停止条件；原小节锚点保留，局部读取与同会话复用不依赖宿主自动裁剪。参数、完整范围、截断、退出码与 record 机制分别归工具箱 references/wiki-validation、source-baseline 及既有 source-link-migration，README 只作导航，不维护第二份手册。工程专项表移至 maintain/verify-engineering，仅 facts／类型／LSP 等任务命中时加载；普通写页不加载。是否检查／刷新及沿用条件仍由对应知识维护流程决定，工具箱缺失可人工核对。普通查询不加载校验文档，SKILL.md 不增加默认内容。

知识来源、采用条件及状态／验证语义集中在 maintain-wiki 的“证据与状态”；write-format 只维护字段形状与取值，不回链语义规则，骨架／版本流程仅保留分支动作。SKILL 入口仅在需要设置或调整状态／验证等级时指向该权威段，已读规则复用，不增加查询默认加载。Ingest 先确认来源、版本及范围；查询证据规则同时适用于生成与审校，不新增 AST／工具箱前置。

普通查询直接复用现有 Wiki／源码，不比较版本或哈希，不在会话首次检查游戏安装、运行源码准备或写哈希缓存。页内状态／证据仍用于判断当前问题是否有覆盖，版本字段只描述已有核验范围；明确要求版本核验、判断是否最新或维护时才进入对应流程。SKILL.md 不再挂接会话级健康检查；此前查询读取成本报告保留当时范围，不外推到新增维护能力。

查询入口与候选选择集中在 query/query：区分已确认标识符、自然语言需求和多机制选型；页面元数据与实际索引均可用于定位，命中后按需读知识章节，不把索引当技术证据。具体主题、归属与选型提示由知识仓维护，包内不复制主题表或增加根入口默认读取；实现与退化处理仍沿用可选查询工具说明。此类规则的定向检查与独立使用测试分开记录，不据作者重放宣称读取成本收益。

query 的输出检查只保留实际加载环境与起步页条件指针，名称查找、GLOBAL 代理及加载阶段的具体知识由共享起步页维护，不在普通查询规则重复教程。无需工程依赖及不读工程历史等公共边界集中在 SKILL.md，子流程只保留定向回退与本任务的读取限制；普通 Ingest 只做叶级登记、必要分类入口及已有失效链接修复，不评选新增 Top 30，快捷入口整理由明确索引维护任务触发。

锚点是位置标识，宿主是否裁剪要实际检查；人工按区间读取仍须取得条件、完整必要代码和验证范围。维护已有知识页先读全文；日志只在实际写入时加载 [日志维护](../references/maintain/maintain-log.md)，平时只检查计数和必要尾部，超限整卷原样归档，历史定向追溯。阈值与操作规则只在该 reference 维护，不增加 SKILL.md 默认读取。执行依据以包内对应 reference 为准，不把工程文档变成第二份使用规则。

## 可移植性与验收

安装目录可以移动；不依赖 .claude／.codex 层级、邻仓、工作目录、斜杠命令或专用模型工具。Windows helper 支持 PowerShell 5.1／7，其他平台可按相同数据约定直接操作；脚本可移植不等于 harness 已自主完成任务。

S01 文件／脚本层已通过 14 项隔离定位检查（PowerShell 7／5.1，见 [首次使用](reports/first-use.md)）；2026-10-16 脚本检视后补充 2 项可选路径用例（现 16 项），见 [脚本检视](reports/scripts.md)。S02 的受控查询覆盖名称／需求、骨架扩展、组合缺口、无 Python／缓存回退与工具失效，见 [查询检视](reports/query.md)；未将关键词命中或记录字节称为全面兼容／token 收益。S03 的隔离写入／检查覆盖生成、增修、冲突与拆页，见 [维护检视](reports/maintenance.md)；重组前定向查入链，技术审阅不被结构校验替代，模板无新增必填项。S04 安装发现与定位见 [宿主基础检视](reports/host-basic.md)，自主路由与读取成本见 [独立使用检视](reports/runtime-20261016.md)；其他宿主、权限边界、非 Windows 和游戏测试仅记实际结果。

helper 与共享日志规则的权威源随本包，开发 Skill 由现有 sync_skill_helpers.py 取得独立副本及哈希；变更只同步必要公共约定，不建立运行时跳转。

后续随扩库持续评测，按已有覆盖、部分覆盖和完全缺页分别报告正确性、实际读取、重复与回退；已有覆盖评估复用收益，部分覆盖检查组合与补查，缺页检查定向回退与停止。成本对照保持同任务／环境与验证程度可比，不预设比例；基础可用、内容覆盖、游戏运行与 token 收益分别验收。只把真实流程失败转为窄修，不用未覆盖内容推动规则或工具膨胀。

## 经验提炼与版本增量维护

SKILL.md 保留任务路由及简短共同边界，空库初始化单列，更新影响说明直达 write-update；description 覆盖经验提炼、初始化、报告生成和版本复查，不硬编码路由数量。仅生成报告且版本／快照已确认时，不加载页面修补或批量协议。入口明确游戏源码与输入模组只读，共享写入由用户维护请求触发。extract-mod 定向分析用户指定的模组／功能及专属框架和资源依赖，先对照已有内容，确有共享缺口才读写入规则；maintain-skeleton 只负责骨架证据、门槛与写入，直接增补不加载模组分析。最小通用组装归 cookbook，机制归 reference，专属实现留模组 Wiki。模组来源简记在验证记录，sources 继续只存已核验游戏文件，去耦与游戏行为分开核验。

maintain-version 为轻量入口，独立修补使用范围／基线、更新条目复用、局部修订及停止条件；选择跨页统一筛选、批量沿用或集中基线收尾时才追加 maintain-version-batch，不设置页数阈值。维护／批次／会话的范围在主流程定义，检查按输入和覆盖范围复用，不因换会话或进入下一批自动全检；协议明确原始等价不 record，其他分支按实际变化处理。机械定位工具可直接用于局部任务，不为此加载批量分类；工具调用及 record 机制仍指向校验入口／工具箱，不复制细节。BUILD 与页版本筛范围，未知或缺旧输入不能当无变化；源码仍不提交。

批量沿用的 active 初筛不足以证明页内无未决项；共同协议先局部读取验证／未决项章节及正文状态标记，影响已采纳结论或范围不明者转定向复查。扫描范围、分流与复用规则仅在批量协议维护，不要求逐页全文或重新审阅未变源码，也不将扫描无命中当作无遗漏证明。

仅实际派发／交接版本任务时，追加 assets/prompts/version-batch 的同骨架工作单；集中核对切片与当前候选／任务占用、旧新实际输入及已有证据范围，不增加每次派发全检。工作组只写互斥页面并返回实际修改／检查与阻塞，主代理核验迁移落地后统一检查、按需 record 及核对队列；页内声称、哈希记录或出队均不单独充当完成证明。派发细节留模板，不复制到默认入口或增加知识页状态字段。

游戏跨版本维护默认先建立或复用匹配版本的简短报告，随每批知识页修订增补变化、条件、证据与页面链接；机械沿用集中保存在报告 index 的“Wiki 沿用记录”，其他修补无适用报告时可在页内简记。写法与独立进度口径由 write-update 维护，不把完整报告作为修页前置。不能仅指向会归档的当前日志或可重建 output，日志仍只存操作摘要；各分支复用已完成范围的引用检查，不将局部批量扩大为全库检查。

版本修补先复用匹配快照的已核验更新条目，缺口才读 diff／必要实现，并将新条件或纠错同批回写 updates。新建／实质增修 detail 的最小具名字段与条目状态由 write-update 维护，版本维护／适配查询按实际证据和接入条件匹配决定复用；旧表／自由文本已有同等信息时直接提取复用，不能把缺格式误当缺证据，仅随实质修改规范化。变化类型、条目核验状态与适配判断分开，不用报告总体审校代替局部判据。三类批量沿用条件在[批量协议](../references/maintain/maintain-version-batch.md)，单页依据与修订在[主流程](../references/maintain/maintain-version.md)；相同代码不证明函数身份，CRLF／BOM／缺末尾换行页不生成文本补丁。报告可局部积累，不强制全量流水线，不增加默认入口、模板字段或 AST 依赖。

文件／行号变化只作线索，行为是否有效须核验；只复查部分结论不升级整页版本或沿用旧游戏测试。两条流程操作规则已交付，专项任务检视仍待办，不能用 S04 的局部维护样本替代；查询不额外加载它们，不依赖新工具、完整 AST 或 codegraph，不增加后台监测／自动提交。详细进度在 PLAN。
